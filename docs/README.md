# docs/

**Your finished, stable documentation.** Things graduate here from [brainstorming/](../brainstorming/) once they stop changing.

Empty right now — that's correct at this stage. It exists so there's an obvious destination when a document settles.

## What will live here eventually

| Document | Graduates from | When |
|---|---|---|
| `design.md` — the locked design: what this aircraft is and why | brainstorming 01–03 | Once parts are ordered |
| `assembly.md` — how this specific aircraft goes together | build-log entries | After first successful build |
| `preflight-checklist.md` — the printable card you actually carry | flight-logs template | Before first flight |
| `maintenance.md` — inspection intervals, what to check after a crash | flight-logs patterns | After a few flights |
| `troubleshooting.md` — symptoms → causes, learned the hard way | build-log failures | Ongoing |
| `emergency-procedures.md` — flyaway, LiPo fire, injury, lost link | — | Before first flight |

## The distinction that keeps this useful

- **brainstorming/** — thinking. Messy, contradictory, revised constantly.
- **build-log/** — history. Append-only, dated, never revised.
- **docs/** — conclusions. Clean, current, revised only when the truth changes.

If a document here is out of date, fix it. If a build-log entry is out of date, leave it alone — that's the point of it.
