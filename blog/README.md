# blog/

The public build log, published to GitHub Pages. Source lives here; the built
site is generated by [`.github/workflows/pages.yml`](../.github/workflows/pages.yml)
on every push to `main` that touches `blog/`.

You do **not** need Ruby installed locally to publish. GitHub builds it.

## Writing a post

Create one file in [`_posts/`](_posts/) named `YYYY-MM-DD-short-slug.md`:

```markdown
---
layout: post
title: "The title, in sentence case"
stage: "Build · Entry 07"
date: 2026-09-14
summary: >-
  One or two sentences. This is what shows on the index page and in
  search results, so make it say something.
---

Body in Markdown.
```

| Field | Required | Notes |
|---|---|---|
| `layout` | yes | Always `post` |
| `title` | yes | |
| `date` | yes | `YYYY-MM-DD`, must match the filename |
| `summary` | no | Falls back to the first paragraph if omitted |
| `stage` | no | Small label above the title, e.g. `Build · Entry 07` |

Then:

```bash
git add blog/_posts/2026-09-14-my-post.md
git commit -m "post: my post"
git push
```

Live in about a minute. Watch progress under the repo's **Actions** tab.

## Relationship to the rest of the repo

- [`build-log/`](../build-log/) is the raw, append-only record — written the same
  day, for debugging.
- `blog/_posts/` is the **edited, public-facing** version of that material.

Write the build-log entry first, for yourself. Turn it into a post when there's
something worth reading. Not every build-log entry needs to become a post.

## Images

Put them in `assets/img/` and reference them relative to the site root:

```markdown
![ESC solder joints]({{ '/assets/img/2026-09-14-esc-joints.jpg' | relative_url }})
```

Resize before committing — a repo full of 6 MB phone photos gets unpleasant fast.

## Editing the design

- [`assets/css/style.css`](assets/css/style.css) — all styling; light and dark
  palettes are CSS custom properties at the top of the file.
- [`_layouts/`](_layouts/) — page structure.
- [`index.html`](index.html) — the front page, including the status chips
  (stage / hardware / flights / spent). **Update those as the project moves.**

## Local preview (optional)

The system Ruby on macOS is 2.6 and too old for Jekyll 4. If you want a local
preview:

```bash
brew install ruby
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
cd blog && bundle install && bundle exec jekyll serve
```

Then open <http://localhost:4000>. Skipping this is fine — pushing and checking
the live site works too.
